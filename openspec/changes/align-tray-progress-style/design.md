## Context

当前应用将图标宽度值直接当作物理像素，并生成高度为 16 的不透明 RGBA 画布；进度条从画布边缘开始绘制。当前 macOS tray builder 还固定启用 template icon 模式，因此 RGBA 颜色不能可靠地作为彩色图标显示。

参考工程把用户配置视为 macOS 逻辑点宽度，在渲染入口转换为 Retina 物理像素，并使用透明画布、内缩轨道和圆角裁剪。颜色模式、阈值边界和绘制逻辑集中在显示配置与渲染层。

## Goals / Non-Goals

**Goals:**

- 让横向进度条在不同宽度和百分比下保持稳定的几何比例。
- 支持单色、阈值和彩虹阈值视觉，并让圆环、横条和柱状图共享颜色语义。
- 明确定义颜色基于当前选中 `LifeMetric` 的显示百分比，余生和已过不自动反转。
- 让设置值使用逻辑点宽度，渲染器负责转换为 Retina 物理像素。
- 让 macOS 彩色图标保留真实 RGBA，并通过实际托盘验证，而不只验证像素数组。
- 使用 serde 默认值和边界归一化读取旧的 `desktop.toml`。

**Non-Goals:**

- 不改变寿命计算、profile 数据或生命指标的计算语义。
- 不引入前端框架、额外 IPC 层或新的图像处理依赖。
- 不重做托盘菜单、设置窗口布局或非图形文本模板的产品设计。
- 不将阈值颜色解释为健康/危险诊断；颜色只表达当前显示百分比所属区间。

## Decisions

### 1. 保持显示配置与渲染器分层

在现有 Rust 配置模型中增加颜色模式、阈值边界和圆角配置；将像素绘制拆成可测试的几何与颜色辅助逻辑。设置命令只负责加载、校验和保存配置，托盘事件处理保持薄层。

### 2. 使用逻辑点宽度并在渲染入口转换

保留现有设置值的用户可见宽度语义为逻辑点，范围采用 `22..=200`；渲染时先 clamp 逻辑点，再转换为物理像素：

```text
wide_px = icon_width_pt * 2
canvas = wide_px × 48 physical pixels
bar    = (x=2, y=4, width=wide_px-4, height=40)
```

圆环和柱状图使用固定的 `44×44` 物理像素画布。若旧配置缺少宽度或超出范围，读取后使用默认值或归一化值；保存时写入规范化值。设置滑块显示逻辑点，不显示物理像素。

### 3. 透明画布与统一圆角裁剪

所有图形图标先以透明 RGBA 初始化。横条在内缩轨道内绘制，轨道和已填充区域共用同一圆角裁剪边界，避免宽度较小时填充端点出现方块或越过轨道。默认圆角半径为 20 个物理像素，并限制为轨道高度的一半。

### 4. 颜色映射只看显示百分比

渲染入口使用 `DisplayState.percent`，不再根据 `LifeMetric` 二次解释。默认边界为 lower=30、upper=70：百分比低于 lower 使用红色，落在 lower..=upper 使用橙色，高于 upper 使用绿色。这样余生 86% 与已过 86% 都是绿色；该规则在两种 metric 下分别测试，避免实现阶段误加反转。

单色模式使用现有深色填充和灰色轨道。普通进度条只显示当前区间填充色与轨道；彩虹阈值条则在轨道中预绘制红、橙、绿区间，当前百分比之后使用低透明度轨道色。颜色常量保持与参考工程一致，并集中定义以便后续调整。

### 5. macOS 不对生成的进度图标强制使用 template 模式

移除 tray builder 对所有图标无条件设置 template 的行为。生成的单色和阈值进度图标均以真实 RGBA 交给 Tauri，确保彩色模式不被系统转换为单色蒙版；如果未来保留 template 行为，只允许对不需要颜色的基础单色图标单独启用。验证必须包含 macOS 实机托盘观察，因为 RGBA 像素测试无法证明系统最终显示颜色。

### 6. 配置校验与兼容

颜色模式、边界和宽度均提供 serde 默认值。边界在加载、保存或渲染前归一化为合法有序区间；错误配置不影响 profile 读取。新增显示字段继续存储在 `desktop.toml`，不写入 `profile.toml`。

## Risks / Trade-offs

- Retina 物理尺寸会使生成的 RGBA 缓冲区约增加到当前的数倍，但托盘刷新频率低且图标尺寸受限，换取稳定的 macOS 显示质量。
- 移除 template 模式后，macOS 深色/浅色菜单栏不会自动替换图标颜色；真实 RGBA 是颜色模式正确显示的必要取舍，单色配色需在实机上确认可读性。
- 颜色语义采用“当前显示百分比”而非“剩余健康度”，规则简单一致，但可能不满足用户对“已过人生”颜色反向表达的直觉；本 change 明确不扩展为另一套语义。
- 旧配置中的宽度值可能原本按物理像素理解；迁移时优先保持用户设置的数值与滑块体验，并通过实机检查防止宽度翻倍造成回归。
