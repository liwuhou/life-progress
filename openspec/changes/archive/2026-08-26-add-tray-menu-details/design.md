## Context

当前 Tauri 应用用固定的“设置/退出”菜单构建托盘，左键 `TrayIconEvent::Click` 还会主动打开设置窗口。生命计算已经在 `display_state` 中得到当前 metric 的百分比以及已过/剩余天数，但这些数据尚未进入菜单状态。

需求必须继续使用原生菜单，不创建额外 WebView 浮窗；菜单项需要在运行期间更新，因此菜单项引用和刷新调度需要由应用状态持有。

## Goals / Non-Goals

**Goals:**

- 在原生菜单顶部显示已过天数、剩余天数和当前 metric 百分比。
- 让菜单摘要、托盘标题和图标来自同一次已校验的生命状态计算。
- 在启动、保存设置和本地日期变化时刷新菜单。
- 让左键只触发原生菜单，避免与设置窗口双重触发。
- 在未配置 profile 时保持菜单可用且不显示伪造的个人数据。

**Non-Goals:**

- 不创建自定义浮窗、WebView 菜单或新的前端页面。
- 不改变寿命计算的输入、预期寿命或颜色语义；仅统一当前日期的本地日历语义，确保跨日刷新与领域计算使用同一日期。
- 不增加 profile 或 desktop preferences 的持久化字段。
- 不让摘要项成为可点击的快捷操作。

## Decisions

### 1. 使用禁用的原生菜单项承载摘要

使用三个不可交互的菜单项作为固定菜单头部：`已过：—`、`剩余：—`、`进度：—`。它们位于分隔线前，设置和退出位于分隔线后。禁用状态沿用 macOS 原生菜单的辅助信息视觉，不需要自定义绘制。

有 profile 后将文本更新为 `已过：N 天`、`剩余：N 天` 和 `进度：P%`；没有 profile 时保留破折号，不暴露或猜测个人数据。

### 2. 将摘要项引用存入 Tauri managed state

在 tray 初始化时创建并保存摘要 `MenuItem` 引用，菜单通过 `MenuBuilder` 组装并加入分隔线。刷新函数从 `AppHandle` 取得该状态，更新三个菜单项文本；同一个刷新入口同时更新 tray title 和图标，避免菜单与图标读取到不同的 profile/preferences。

### 3. 扩展内存显示状态而非持久化模型

在现有显示状态计算结果中保留所选 metric 的 `percent`/`days`，并补充已过天数和剩余天数两个运行时字段。字段仅用于当前进程的托盘展示，不写入 `profile.toml` 或 `desktop.toml`。百分比继续按 `LifeMetric` 选择，两个天数始终同时显示。

### 4. 启动和设置保存立即刷新

应用完成 tray 构建后，如果 profile 已存在，读取 profile/preferences 并调用统一刷新入口；保存设置命令成功持久化后复用同一入口。无 profile 时只保留摘要占位项、设置和退出菜单，并继续打开设置页完成首次配置。

### 5. 以本地日期变化为刷新信号

启动一个轻量的应用级刷新循环，每分钟检查本地日期是否变化；只有日期跨越时才重新读取配置并刷新显示。分钟级检查避免复杂的 DST/睡眠唤醒计算，同时不会造成持续的菜单项写入。循环使用应用句柄，不记录 profile 内容；应用退出时线程随进程结束。

### 6. 明确左键由原生菜单处理

删除自定义左键 `TrayIconEvent` 中打开设置的行为，并显式启用 Tauri 的 `show_menu_on_left_click(true)`（若平台默认已启用也保持显式配置）。菜单的“设置”项继续由 `on_menu_event` 打开设置窗口；这样左键不会同时弹出菜单和设置窗口，且右键行为仍由原生菜单处理。

### 7. 统一本地日历日期语义

日期变化检查与寿命进度计算都使用 `chrono::Local::now().date_naive()`。不使用 UTC 派生日期，避免 UTC+ 时区在本地午夜刷新后仍显示前一天，或在 UTC 午夜才刷新导致本地菜单整天陈旧。增加固定日期边界测试，覆盖本地前后两天的变化判定。

## Risks / Trade-offs

- 禁用菜单项在 macOS 上颜色较弱，但与原生菜单一致，且摘要不是操作入口；若可读性不足，再考虑减少项目数量而不是自绘菜单。
- 每分钟检查日期会保留一个轻量线程；它不进行网络请求，也不打印个人数据，换取跨午夜和睡眠唤醒后的可靠刷新。
- 配置文件被外部修改时，刷新循环读取失败应保留上一次可用显示并静默处理；启动和设置保存仍然传播明确错误。
- 菜单文本长度受原生菜单宽度约束，天数使用紧凑的中文格式，避免加入生日、寿命来源等进一步信息造成菜单过载。
